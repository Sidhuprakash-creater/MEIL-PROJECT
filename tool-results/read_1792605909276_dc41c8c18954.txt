    18→    18→## 2. NON-NEGOTIABLE ROLE DEFINITION
    19→    19→
    20→    20→SUPER ADMIN = GROUP ADMIN.
    21→    21→
    22→    22→These are two names for the SAME role in this project. Never create two separate roles, dashboards, account types, or authorization layers for them.
    23→    23→
    24→    24→The Group Admin is the highest organizational-level administrator in this application's defined role hierarchy.
    25→    25→
    26→    26→The Group Admin can manage the complete authorized organizational scope, including subsidiaries, business units, projects, users, submissions, approvals, ESG analytics, audit records, and consolidated BRSR reporting.
    27→    27→
    28→    28→The Group Admin is responsible for creating, reviewing, coordinating sign-offs for, and finalizing the consolidated BRSR report according to configured permissions and reporting requirements.
    29→    29→
    30→    30→### Existing role hierarchy
    31→    31→
    32→    32→Group Admin
    33→    33→  └── Subsidiaries
    34→    34→      └── Subsidiary Manager
    35→    35→      └── Subsidiary Admin
    36→    36→          └── Business Units
    37→    37→              └── BU Manager
    38→    38→              └── BU Admin
    39→    39→                  └── Project / Site Users
    40→    40→
    41→    41→### Seven Data Entry User roles
    42→    42→
    43→    43→1. Environment Data User
    44→    44→2. Finance & Resource Contributor
    45→    45→3. HR User
    46→    46→4. EHS / Safety User
    47→    47→5. Procurement User
    48→    48→6. CSR / Community User
    49→    49→7. Compliance User
    50→    50→
    51→    51→There are 11 defined role types in total: one Group Admin, two subsidiary roles, two BU roles, and seven data-entry roles.
    52→    52→
    53→    53→These are role types, not fixed user counts. Support multiple users in each role and multiple projects, BUs, and subsidiaries.
    54→    54→
    55→    55→Preserve the organization hierarchy:
    56→    56→
    57→    57→GROUP → SUBSIDIARY → BUSINESS UNIT → PROJECT / SITE
    58→    58→
    59→    59→The Group Admin must be able to inspect the entire organization through searchable tables, hierarchy views, detail pages, filters, and drill-down navigation.
    60→    60→
    61→    61→Do not assume actual company counts, real users, reporting figures, or organizational records. Use existing backend data where available and clearly identified demo data when necessary.

    82→    82→- Route the report through configured reviews and required sign-offs.
    83→    83→- Finalize, version, and export the approved report.

  1247→  1247→- Reporting period.
  1248→  1248→- Organization scope.
  1249→  1249→- Calculation rule and version.
  1250→  1250→- Units and conversion factors.
  1251→  1251→- Validation state.
  1252→  1252→- Approval state.
  1253→  1253→- Calculation timestamp.
  1254→  1254→- Report version.
  1255→  1255→
  1256→  1256→Avoid double-counting when aggregating data from projects, BUs, and subsidiaries.
  1257→  1257→
  1258→  1258→Use explicit consolidation boundaries and tested aggregation rules.

  1260→  1260→Any correction to finalized data must follow a controlled revision process.
